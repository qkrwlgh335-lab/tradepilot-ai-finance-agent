# KB TradePilot 데모 실행·검증 가이드

## 전제

- Node.js 18 이상
- 일반 실행에는 npm 패키지 설치와 API 키가 필요하지 않음
- `file://` 더블클릭이 아니라 아래 로컬 서버로 실행

## 기본 실행 — API 키 불필요

Windows에서는 `START_DEMO.cmd`를 더블클릭하면 서버와 브라우저가 자동으로 열립니다.
`START_DEMO.cmd`는 `npm start`(→ `scripts/start-demo.mjs`)를 호출하는 얇은 래퍼로,
데모 서버를 띄운 뒤 실제 `/` 응답이 200으로 확인될 때까지 기다린 다음 브라우저를 엽니다.
고정된 sleep이 아니라 실제 준비 상태를 확인합니다. 심사자에게는 이 방법을 우선 안내합니다.

수동 실행:

```powershell
npm test
npm start
```

또는 브라우저를 열지 않고 서버만 띄우려면 `node scripts/dev-server.mjs`.

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 기본 모드는 결정론적 로컬 설명이며,
위험 계산·시나리오·온톨로지 자격판정·RAG·상담 브리프는 외부 AI 없이 동작합니다.
시맨틱 RAG 또는 로컬 자연어 의미 분류를 처음 사용할 때는 브라우저가 임베딩 모델을
CDN에서 지연 다운로드할 수 있습니다. 인터넷이 없거나 다운로드가 실패하면 공식 문서
키워드 검색과 자연어 키워드 분류로 각각 자동 폴백하므로 핵심 흐름은 중단되지 않습니다.

## 공식 시장데이터 캐시 갱신

기본 제출본은 이미 검증된 ECB 공식 일별 기준환율 캐시를 포함하므로 오프라인에서도
동작합니다. `npm start`로 서버를 시작하면 첫 `/` 접속에서 서버가 ECB 공식 데이터를
갱신 시도합니다. 정적 자산(`/js`, `/css`, `/data`) 요청은 갱신을 유발하지 않습니다.

갱신은 서버(Node)에서만 수행되며, **브라우저는 ECB 엔드포인트를 직접 호출하지 않습니다.**
성공 시 30분 TTL, 실패 시 5분 cooldown, 외부 호출 timeout 5초를 적용합니다. 실패하면
기존 검증 캐시가 그대로 유지되고 앱은 정상 실행됩니다.

**오프라인 데모(자동 갱신 완전 차단):** 환경변수 `KB_MARKET_AUTO_REFRESH=off`.

```powershell
$env:KB_MARKET_AUTO_REFRESH="off"; npm start
```

```bash
KB_MARKET_AUTO_REFRESH=off npm start
```

허용값: `off`, `false`, `0`, `no`(off) / 그 외 또는 미설정(auto — 기본값). 이 스위치는
**서버 측**에서만 판단하며 브라우저 번들에는 노출되지 않습니다. 완전 오프라인에서도
검증 캐시로 A/B/C 전체 흐름이 무중단 완주됩니다.

수동 갱신(예: 캐시를 미리 최신화하고 오프라인에서 시연):

```powershell
npm run refresh:market-data
```

### 시장데이터 상태

브라우저 배지가 표시하는 4가지 상태:

- **cached** — `🗂️ 검증된 공식 일별 데이터 캐시 · ECB · 기준일 YYYY-MM-DD`.
  현재 자동 갱신 경로의 실제 런타임 상태. `refreshMarketData`는 성공 시에도 항상
  `status:"cached"`를 저장하며, 이 UI 문구는 언제 갱신되었는지("최근" 등)를 계산하지
  않고 오직 **기준일**만 표기합니다. 캐시가 오래돼도 "최근"이라고 부르지 않습니다.
- **demo** — `🧪 예시 시장데이터 · 실제 거래 전 확인 필요`. 예시 데이터 상태.
- **unavailable** — `⛔ 시장데이터를 확인할 수 없어 계산을 중단했습니다`.
  분석 실행 게이트(`validateMarketDataForAnalysis`)가 fail-closed로 계산을 시작하지
  않습니다(같은 판정 함수를 배지와 게이트가 공유).
- **live** — **향후 KB 내부 직접(real-time) Provider용 예약 상태**. 현재 ECB Node
  갱신 경로에서는 절대 표시되지 않으며, 배지에는 `직접 공식 데이터 (예약 상태)`로만
  나타납니다. 앞으로 KB 내부 실시간 스트림이 연결될 경우에만 활성화됩니다.

브라우저 문구에는 **"실시간"·"체결환율"·"KB 우대환율"** 등의 표현을 쓰지 않습니다.

호출은 Node에서만 `data-api.ecb.europa.eu` 고정 호스트로 수행됩니다. 응답 스키마,
날짜, 통화 집합, 양수 값과 최소 관측치를 모두 검증한 뒤 `fx.json`, `fx-vol.json`,
`market-sources.json`을 임시 파일에서 원자적으로 교체합니다. 실패하면 기존 캐시를
그대로 보존합니다. 브라우저는 공식 API를 직접 호출하지 않습니다.

현재 거래국 선택은 71개, 계산 통화는 29개입니다. 거래국의 현지통화가 지원되지 않으면
자동으로 임의 환율을 만들지 않으며, USD 등 실제 계약 결제통화를 사용자가 선택해야 합니다.

### 공식 양국간 상품 교역 통계 캐시

첫 `/` 접속에서는 시장데이터·국가 거시지표와 독립적으로 UN Comtrade의 대한민국
신고 기준 연간 상품 총교역 캐시도 갱신 시도합니다. 브라우저는 UN Comtrade API를
직접 호출하지 않고 `data/bilateral-trade.json`만 읽습니다. 수동 갱신은 다음과 같습니다.

```powershell
npm run refresh:bilateral-trade
```

Node 갱신기는 고정 공식 호스트, 대한민국 신고국 코드(410), 연간·HS·TOTAL·수출/수입
응답 신원과 값·중복·응답 상한을 검증한 뒤 성공한 경우에만 캐시를 원자적으로 교체합니다.
실패하면 기존 검증 캐시를 보존합니다. 파트너 코드가 공식 ISO2에 연결되지 않는 국가는
`교역 통계 미확인`으로 표시합니다. 값은 기업별 거래·예측·국가위험등급이 아니며 CFaR,
유동성, 상품 자격판정에 전달하지 않습니다. `KB_MARKET_AUTO_REFRESH=off`이면 이 갱신도
호출하지 않습니다.

기본 데모 순서:

1. A사 샘플 불러오기
2. 기업 형태·기업 규모·위험성향·지원 목적 선택
3. `상품 자격 확인 정보`는 아는 사실만 선택하고, 모르는 항목은 `모름·확인 필요` 유지
4. 기존 헤지 없음 확정
5. 분석하기 → 입력 확인 → 분석 실행
6. `내 기업의 금융 액션 플랜` 3개 확인
7. 상단 상담 후보에서 추천 이유·확인된 자격·주의사항·다음 행동 확인
8. 자연어에 `바이어 대금 회수가 미뤄지면?`을 입력해 로컬 의미 분류와 대상 질문 확인
9. `입금 1개월 지연`을 실행해 CFaR·유동성·후보 상태의 전후 변화 확인
10. 필요할 때만 `판정 근거 자세히 보기`와 `상세 계산·분석` 펼치기
11. 선택 후보로 상담 브리프 초안 생성

## 선택적 외부 설명 시연

키는 브라우저에 입력하거나 저장하지 않습니다. 프록시 프로세스의 환경변수로만 설정합니다.
아래 모델 ID는 구성 예시이며, 실제 호출 시에는 사용하는 Anthropic 계정에서 이용 가능한
모델 ID인지 확인해 `ANTHROPIC_MODEL`에 설정합니다.

PowerShell:

```powershell
$env:ANTHROPIC_API_KEY="발급받은-키"
$env:ANTHROPIC_MODEL="claude-sonnet-4-20250514"
npm run proxy
```

bash:

```bash
export ANTHROPIC_API_KEY="발급받은-키"
export ANTHROPIC_MODEL="claude-sonnet-4-20250514"
npm run proxy
```

또는 저장소에 커밋되지 않는 `.env`를 `.env.example` 형식으로 만들 수 있습니다.
정적 앱과 프록시는 각각 `127.0.0.1:8000`, `127.0.0.1:8787`에서 실행합니다.
Windows에서는 `외부AI_설정후_실행.cmd`를 더블클릭하는 것이 가장 간단합니다. 스크립트가
`.env.example`을 `.env`로 복사해 메모장으로 엽니다. 기본 모델 ID는 이미 채워져 있으므로
본인의 `ANTHROPIC_API_KEY` 값만 저장하고 메모장을 닫으면 됩니다. 계정에서 기본 모델을
지원하지 않을 때만 `ANTHROPIC_MODEL`을 변경하세요. 그러면
`START_DEMO.cmd`가 실행됩니다. `npm start`와 `START_DEMO.cmd`는 유효한 `.env`가 있으면
loopback 프록시도 자동 시작하고, 설정이 없거나 프록시 시작이 실패하면 로컬 설명 모드로
계속 실행합니다. 실제 키 값은 콘솔·브라우저·감사로그에 출력하지 않습니다.
화면에서 `external`을 고른 뒤 AI 설명 버튼을 누르면 실제 전송 객체를 확인하고
승인할 수 있습니다. 키·프록시·네트워크가 없으면 규칙 설명으로 자동 복귀합니다.
자연어 시나리오의 `선택적 외부 AI 실험 어댑터`도 기본은 꺼져 있습니다. 사용자가
직접 체크하고 로컬 분류가 확신하지 못한 경우에만 마스킹된 문장을 `/api/intent`로
보냅니다. 응답은 `type`과 `confidence`만 허용하며 대상·수치·실행값은 받지 않습니다.

`internal` 모드는 실서비스용 교체 지점일 뿐 현재 미구현이며 화면에서 비활성화됩니다.
Claude Code 로그인이나 구독 인증정보는 이 앱이 사용하지 않습니다.

## 보안 경계

이 로컬 프록시가 금융권 실서비스 보안을 완성한다고 주장하지 않습니다. 데모 방어선은
loopback bind, purpose enum, 서버 측 중첩 스키마 재검증, 서버 측 프롬프트,
32KB 크기 제한과 30초 타임아웃의 조합입니다. CORS 하나만으로 안전하다고 보지 않습니다.
실서비스에서는 KB 내부 LLM/Gateway, 중앙 비밀관리, 인증·권한, 변조방지 감사로그로
교체해야 합니다.

## 자동(Node) 통합 게이트

`npm test`는 브라우저를 띄우지 않고 다음 계약을 자동 검증합니다.

- 샘플 입력 → 프로파일 → CFaR·유동성 → 전략 → 온톨로지 추천 → RAG 근거 → 상담
  브리프가 하나의 파이프라인으로 이어지는지
- A사 금융 골든, 금융 불변조건, 동일 입력의 결정론적 재현
- 부적격 상품 추천 0건, 필수정보 누락 시 `eligible` 0건
- 모든 추천 후보의 `reasoningPath`, 공식 출처, 자격 규칙 근거
- RAG·외부 LLM 실패가 계산과 온톨로지 판정을 변경하지 않는지
- 외부 전송 중첩 스키마, 의도 응답의 엄격한 `type+confidence` 스키마,
  감사로그 원문 미저장, 키·프록시가 없을 때의 폴백
- 합성 코퍼스·독립 holdout 분리, 임베딩 해시 최신성, 낮은 신뢰도·대상 모호 시 실행 0건

## 수동 브라우저 검증 체크리스트

다음은 사람이 실제 화면과 개발자 도구를 확인하는 절차이며 **자동 Playwright E2E가 아닙니다**.
각 항목을 최종 제출 환경에서 직접 확인하고, 실패하면 콘솔·입력값·현재 모드를 함께
기록합니다.

- [ ] 기본 `mock` 모드와 API 키 없는 상태에서 샘플 A의 전체 흐름을 완주한다.
- [ ] `test/fixtures/t10-valid.csv`를 불러오고 CSV 파싱 결과와 수출/수입·수취/지급 축을
  확인한 뒤 사용자가 확정해야 분석으로 넘어가는지 확인한다.
- [ ] A사 액션 플랜이 정확히 3개이고, CFaR `₩45,066,367` 및 상세 계산 영역이 처음에는 접혀 있는지 확인한다.
- [ ] 추천 후보명·추천 이유·확인된 자격·주의사항·다음 행동이 기술 추론 경로보다 먼저 보이는지 확인한다.
- [ ] 원시 온톨로지 경로와 RAG 근거는 `판정 근거 자세히 보기`를 열기 전에는 보이지 않는지 확인한다.
- [ ] CFaR에 `보수적 단순합 — 상관관계 미반영` 취지가 표시되고 잔여 위험과 헤지 비용이
  합산되지 않는지 확인한다.
- [ ] 목적별 판정이 `추천 후보`·`정보 필요`·`고객 부적격`·`공식정보 미확인`으로 분리되고,
  추천 후보마다 공식 근거와 자격 규칙 근거가 별도 블록에 표시되는지 확인한다.
- [ ] B사에서 제조기업·지원 업종·데모보증기관 수입보험·신용등급·상담채널 사전확인을 `충족`으로
  확정하면 `공급망 수입금융 프로그램(합성)`가 상담 후보가 되고, 한 항목을
  `모름`으로 되돌리면 정보 필요 카드와 KB 공식 문서 링크가 표시되는지 확인한다.
- [ ] 인터넷이 가능한 환경에서는 RAG 시맨틱 검색 상태를, 모델 로딩 실패·오프라인
  환경에서는 키워드 폴백을 확인한다. 임계값 미달 후보는 강제로 채우지 않고
  `관련 근거 없음`으로 표시되는지 확인한다.
- [ ] 프록시를 끈 상태에서 `external` 승인 후 규칙 설명으로 복귀하며 계산·추천 결과가
  변하지 않는지 확인한다.
- [ ] 선택적으로 프록시를 켠 경우 설명 요청은 `purpose`, `analysisPayload`만,
  의도 요청은 `purpose`, `maskedText`만 포함하고 브라우저가 Anthropic API를 직접
  호출하지 않는지 확인한다.
- [ ] 자연어 의미 분류에서 높은 신뢰도 문장은 고정 프리셋 미리보기로, 낮은 신뢰도
  문장은 추가 질문으로 가며 승인 버튼이 생기지 않는지 확인한다.
- [ ] `USD 수취대금 회수가 미뤄지면?`은 일치하는 두 거래만 질문하고,
  `독일 EUR 수취대금 회수가 늦어지면?`은 일치 후보 없음으로 실행을 차단하는지 확인한다.
- [ ] `internal` 옵션이 `현재 미구현`으로 비활성화됐는지 확인한다.
- [ ] 입금 지연·수취액 감소·불리한 환율 반사실이 실제 변경 입력과 전후 값을 표시하는지
  확인한다.
- [ ] 상담 브리프 제목과 하단에 `초안 · 제출본 아님` 취지가 표시되는지 확인한다.
- [ ] 로컬 설명은 외부 전송 감사로그를 만들지 않고, 실제 external 승인·거부 시도만 세션 감사로그에 남는지 확인한다.
- [ ] 감사로그가 세션 저장소에 최대 100건만 남고 삭제 버튼이 동작하는지 확인한다.
- [ ] 개발자 도구의 `localStorage`·`sessionStorage`에 API 키·토큰이 없고, 전체 시연 동안
  콘솔 오류 0건인지 확인한다.

## 장애 대응

- 화면이 이전 버전이면 `scripts/dev-server.mjs`로 다시 실행한 뒤 강력 새로고침합니다.
- 임베딩 모델 지연 로딩이 실패해도 키워드 근거 검색·키워드 의도 분류로 자동 폴백합니다.
- 외부 설명 실패는 계산·온톨로지 판정·RAG 결과를 변경하지 않습니다.
- 계산 필수값이 없거나 잘못되면 위험을 0으로 보이지 않고 오류 이유를 표시합니다.
