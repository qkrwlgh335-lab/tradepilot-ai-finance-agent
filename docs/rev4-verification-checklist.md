# KB TradePilot rev.4 제출 전 검증 체크리스트

이 문서는 자동으로 확인할 수 있는 항목과 사람이 브라우저에서 확인해야 하는 항목을
구분한다. 검증 중에는 기존 제출 ZIP을 덮어쓰지 않는다. 최종 제출 ZIP 재생성은
발표자료와 제출 문서가 확정된 뒤 별도 승인 하에 수행한다.

## 1. 기준 상태 보존

- [ ] 현재 브랜치가 `codex/award-upgrade`인지 확인한다.
- [ ] `award-ux-v1`, `submission-safe-v1` 태그가 존재하는지 확인한다.
- [ ] `git status --short`에서 기존 미추적 제출 ZIP 외의 변경이 없는지 확인한다.
- [ ] 검증용 ZIP은 `%TEMP%` 등 별도 경로에 생성하고
      `기획안/KB_TradePilot_수출입금융에이전트_제출.zip`을 변경하지 않는다.

## 2. 자동 검사 — 코드·계산·평가

```powershell
npm test
npm run eval
npm run security:scan
```

- [ ] 전체 Node 테스트가 실패 0건인지 확인한다.
- [ ] 금융 골든 6/6이 유지되는지 확인한다.
- [ ] 합성 평가 34건에서 지표 12/12가 통과하는지 확인한다.
- [ ] `source_digest`, `results_digest`, 데이터 버전이 생성 리포트에 있는지 확인한다.
- [ ] 평가 리포트가 현재 평가 소스와 불일치하면 UI가 과거 수치를 숨기는지 확인한다.

## 3. 자동 검사 — 값 기반 보안

`npm run security:scan`은 API 키 환경변수 이름이 아니라 다음처럼 실제 비밀값으로
보이는 문자열을 탐지한다.

- Anthropic·일반 API 키 모양
- AWS Access Key ID 모양
- Bearer 토큰 모양
- JWT 모양

`ANTHROPIC_API_KEY`, `AWS_ACCESS_KEY_ID` 같은 이름과 설정 안내 문구만으로는 실패하지
않는다. 발견 시 실제 값은 로그에 다시 출력하지 않고 파일·종류·행·열만 보고한다.

검증용 최종 패키지는 기존 제출 ZIP과 다른 임시 경로에 생성한다.

```powershell
$verificationZip = Join-Path $env:TEMP "KB_TradePilot_rev4_verification.zip"
npm run package:submission -- --output $verificationZip
npm run security:scan -- --zip $verificationZip
```

- [ ] 패키징 전 단계 디렉터리 검사에서 키 유사 값 0건인지 확인한다.
- [ ] ZIP 바이너리를 문자열로 읽지 않고 임시 폴더에 추출한 뒤 내부 파일을 검사하는지 확인한다.
- [ ] 검증 전후 임시 ZIP의 크기·수정시각이 추출검사 때문에 변하지 않는지 확인한다.
- [ ] 가짜 키를 넣은 프록시 `--check` 실행의 stdout·stderr에 해당 값이 없는지 확인한다.
- [ ] 패키지에 `평가근거/evaluation-report.json`, `평가근거/eval/`,
      `평가근거/발표자료_근거매핑.md`가 포함되는지 확인한다.

## 4. 자동 정적검사와 브라우저 수동 확인의 경계

### 자동 검사 — 정적

- [ ] 브라우저 코드가 `api.anthropic.com`을 직접 호출하지 않는지 확인한다.
- [ ] 브라우저 요청이 허용된 목적과 비식별 payload만 보내는지 확인한다.
- [ ] 소스에 API 키·토큰을 `localStorage` 또는 `sessionStorage`에 저장하는 코드가 없는지 확인한다.
- [ ] 프록시가 loopback에만 바인딩되고 서버 측에서 목적·payload를 재검증하는지 확인한다.

### 수동 확인 — 실제 브라우저

- [ ] 개발자 도구 → Application에서 `localStorage`와 `sessionStorage`를 각각 연다.
- [ ] API 키·Bearer 토큰·JWT·계좌·원문 계약이 저장돼 있지 않은지 확인한다.
- [ ] 세션 감사로그에는 시각·목적·승인·결과 같은 메타데이터만 있는지 확인한다.
- [ ] 감사로그 삭제 버튼을 누르면 세션 로그만 삭제되는지 확인한다.
- [ ] 전체 A/B/C 시연 동안 콘솔 오류·경고가 0건인지 확인한다.

정적 자동검사는 런타임 저장소의 실제 내용을 관찰했다고 주장하지 않는다. 브라우저
저장소는 반드시 위 수동 절차로 최종 확인한다.

## 5. 브라우저 기능 확인

- [ ] `http://127.0.0.1:8000/`에서 앱이 즉시 열리는지 확인한다.
- [ ] A/B/C 샘플이 입력 → 확인 → 위험 → 자격 → 근거 → 반사실 → 상담 브리프로 완주하는지 확인한다.
- [ ] 5단계 헤더와 아이콘·문구·색상을 함께 쓴 4상태 범례가 보이는지 확인한다.
- [ ] 자연어 요청은 대상과 의도만 분류하고 고정 프리셋을 승인 전 미리 보여주는지 확인한다.
- [ ] 대상이 모호하거나 신뢰도가 낮으면 실행 버튼 없이 질문하는지 확인한다.
- [ ] 시장데이터 상태·기준일이 보이고 실시간 연동이라고 과장하지 않는지 확인한다.
- [ ] 평가 카드가 합성 평가 34건·지표 12/12의 현재 리포트 값만 표시하는지 확인한다.
- [ ] 375px 모바일과 데스크톱에서 가로 넘침이 없는지 확인한다.

## 6. 최종 제출 직전

- [ ] 발표자료의 수치를 `docs/rev4-ppt-evidence.md`와 생성 리포트에 다시 대조한다.
- [ ] 실제 KB 내부 심사 성능·전체 고객 성능·실시간 전체 시장 연동을 주장하지 않는다.
- [ ] 임시 검증 ZIP을 삭제하고, 승인 후에만 기본 `npm run package:submission`으로
      실제 제출 ZIP을 새로 생성한다.
- [ ] 최종 ZIP을 별도 폴더에 추출해 실행·문서·평가근거·키 유사 값 0건을 마지막으로 확인한다.
